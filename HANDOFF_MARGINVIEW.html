Cos'è MarginView

MarginView è una web application di controllo di gestione costruita su misura. Permette di caricare dati aziendali tramite file Excel e ottenere analisi interattive, dashboard visive, report PDF e commenti automatici generati da intelligenza artificiale.

ModuloFunzione principaleOutput disponibili
Matrice ABC / Pareto Classifica referenze per fatturato e marginalità (A/B/C), curva di Pareto, analisi rotazione magazzino Dashboard, Export Excel, PDF, Commento AI
Analisi Varianza Marginalità Confronta due periodi e scompone la variazione di margine in Effetto Volume, Mix, Prezzo e Costo Waterfall, tabella pivot, Export Excel, PDF, Commento AI
Analisi di Bilancio Calcola KPI da conto economico e stato patrimoniale su più anni (EBITDA, ROE, ROI, PFN, CCC, FCF) Grafici trend, PDF, Commento AI
Dashboard Panoramica sintetica con accesso rapido ai moduli —

Repository e flusso di lavoro

Repository GitHub: github.com/AM-1989/marginview — account AM-1989 (Alessio Moro). Branch principale: main.

ℹ️
Una modifica al codice non va online da sola

Il flusso è sempre: modifica locale → commit → push su GitHub → deploy sul server. Solo dopo il deploy il sito si aggiorna. GitHub è solo il punto di archiviazione sicuro del codice.

Regola pratica per ogni modifica

  • Prima del deploy: creare un branch separato o annotare il commit corrente come punto di ripristino
  • Modificare solo i file necessari — non espandere il perimetro
  • Eseguire il build locale (npm run build) per verificare che non ci siano errori
  • Leggere il diff prima di committare — controllare ogni riga modificata
  • Commit e push su GitHub
  • Eseguire ./deploy.sh sul server via SSH
  • Verificare su produzione con un file Excel reale
⚠️
Regola assoluta: server/.env non va MAI su Git

Il file contiene password e chiavi API. È già escluso dal .gitignore. Se dovesse comparire in un commit per errore, considera quelle credenziali compromesse e cambiale immediatamente. Le variabili di produzione vivono nel pannello Hostinger, non nel repository.

7
Regole importanti di manutenzione
🔢
Distinguere 0, dato assente e N/D

Un valore a zero è diverso da un dato mancante. Nel codice questi tre stati hanno significati distinti — non vanno confusi nei calcoli.

🤖
L'AI riceve solo dati JSON elaborati, mai l'Excel grezzo

Quando viene richiesto un commento AI, il server invia ad Anthropic solo i valori numerici già calcolati, formattati come testo strutturato. Il file Excel non lascia mai il browser dell'utente.

🎨
Non toccare i calcoli per interventi grafici

Se si modifica solo l'aspetto visivo (colori, layout, testi), non toccare i file src/lib/. La logica è separata dall'interfaccia apposta.

🌐
CORS: aggiornare il pannello, non il codice

I domini autorizzati a chiamare le API sono nella variabile CORS_ORIGIN del pannello Hostinger. Se si cambia dominio, va aggiornata solo quella variabile (e riavviato PM2), non il codice sorgente.

Guida: migrazione email a Brevo (account proprio)
⚠️
Perché è necessario

Attualmente le email di accesso (codice OTP + attivazione account) vengono inviate tramite l'account Brevo dello sviluppatore. Per essere completamente indipendente, Alessio deve avere il proprio account Brevo con le proprie credenziali SMTP.

Come fare (10 minuti, gratuito):

  1. Vai su brevo.com e crea un account gratuito con la tua email aziendale. Il piano gratuito include 300 email al giorno — più che sufficiente.

  2. Una volta dentro, vai su Settings → SMTP & API nel menu in alto a destra.

  3. Clicca su "Generate a new SMTP key". Dai un nome (es. "MarginView produzione") e conferma. Copia la chiave generata — viene mostrata una sola volta.

  4. Annota i valori che ti servono:
    SMTP_HOST = smtp-relay.brevo.com
    SMTP_PORT = 587
    SMTP_SECURE = false
    SMTP_USER = la tua email di login Brevo
    SMTP_PASS = la chiave SMTP generata al punto 3
    SMTP_FROM = l'indirizzo mittente che vuoi mostrare (es. noreply@marginview.it)

  5. Nel pannello Hostinger, entra nelle variabili d'ambiente del progetto e aggiorna i valori SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASS, SMTP_FROM con i nuovi valori Brevo.

  6. Riavvia il processo API via SSH oppure tramite il pannello PM2 di Hostinger con il comando: pm2 restart moro-api

  7. Testa l'invio: prova ad accedere all'app con il tuo account — dovresti ricevere il codice OTP sulla tua email. Se arriva, la migrazione è completata.

✅
Fatto questo, l'app è completamente tua — zero dipendenze esterne

GitHub, Hostinger (app + DB + dominio), Lovable (landing), Anthropic API e Brevo saranno tutti intestati ad Alessio Moro. L'unica migrazione rimasta è questa.
